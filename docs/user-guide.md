# ユーザーガイド

*English: [docs/en/user-guide.md](en/user-guide.md)*

tsmyadmin の画面と操作の説明です。画面構成は phpMyAdmin と同じ 3 階層（**サーバー → データベース → テーブル**）で、左のサイドバーからどの階層にも移動できます。

## 接続（ログイン）

1. 「接続先」で管理者が用意したプリセットを選ぶか、「手動で入力」でサーバー種別・ホスト・ポートを入力します
2. ユーザー名とパスワードを入力して「接続する」。PostgreSQL は接続先データベース名が必要です（省略時は `postgres`）
3. 資格情報はサーバー側のセッションに保持され、ブラウザには署名付きセッション ID の Cookie が置かれます（それとは別に、前回の接続先・ユーザー名・データベース名を localStorage に記憶します。パスワードは記憶しません。共用の端末では他の人に接続先が見えることに注意してください）。無操作が `SESSION_TTL_MINUTES`（既定 30 分）続くと切断され、再接続後は元の画面に戻ります

接続できるホストは管理者が `TSMYADMIN_ALLOWED_HOSTS` で制限しています。一覧にないホストへは接続できません。

### 2 要素認証（ワンタイムコード・パスキー）

サーバーの「セキュリティ」タブで、いまログインしているアカウントに認証アプリのワンタイムコードを追加できます。

1. 「認証アプリで登録する」を押すと、QR コード・鍵（文字列）・`otpauth://` の URI と、回復用コード 10 個が **その場だけ** 表示されます。認証アプリで QR コードを読み取ってください（読み取れない端末では、鍵を手で入力するか URI を貼り付けます）
2. 回復用コードは印刷するかパスワードマネージャーに保存してください。1 つにつき 1 回しか使えず、あとから見返すことはできません
3. アプリに出ているコードを入力して「登録を完了する」。ここで確認できるまでは有効になりません（途中でやめても締め出されません）

次回のログインからは、パスワードのあとにコードを求められます。回復用コードも同じ欄に入力できます。一度受け付けたコードは、その 30 秒の間でも二度は使えません（続けてログインするときは次のコードを待ってください）。

**パスキー**: 管理者が `TSMYADMIN_PASSKEY_ORIGIN` を設定している場合は、「パスキーで登録する」でパスキー（端末の生体認証やセキュリティキー）も使えます。最初の方法として登録したときは、回復用コードがその場で表示されます。ログインではコード欄の下の「パスキーで確認」を押します。パスワードの代わりにはならず、パスワードのあとの 2 要素目です。

登録済みの状態では、同じタブに方法の一覧（認証アプリ・パスキー）が出て、追加や削除ができます。変更には本人確認が要ります。アプリの現在のコードを「コード」欄に入れるか、欄を空のままにしてパスキーで確認します（回復用コードは使えません）。

すべて解除するには「2 要素認証を解除する」。**端末を失って回復用コードも無い場合、自分では戻せません**。管理者に「ユーザー」タブからの解除を依頼してください。管理者が全アカウントに必須としている場合（`TSMYADMIN_REQUIRE_2FA`）は、登録を終えるまで他の画面は使えません。

## 表示言語

画面右上の言語メニューで日本語 / English を切り替えられます（切り替えるとページが再読み込みされ、選択はブラウザに保存されます）。初回はブラウザの言語設定に従います（英語系なら English、それ以外は日本語）。

## 画面の共通要素

| 要素 | 説明 |
|---|---|
| サイドバー | データベース → （PostgreSQL はスキーマ →）テーブルのツリー。上部の入力欄でテーブル名を絞り込めます。その下に「お気に入り」（テーブル名の横の星で追加・解除）と「最近使ったテーブル」（直近 10 件）を表示します（このブラウザに、接続先ごとに保存）。ヘッダー左端のボタンか `⌘/Ctrl + B` で表示 / 非表示（設定はブラウザに記憶） |
| タブ | 階層ごとの機能（表示 / 構造 / SQL / …）。URL に状態が入るので、ページをそのまま共有・ブックマークできます |
| コンソール | ヘッダーの「コンソール」で、画面の下に SQL コンソールを常駐させます。表示中のデータベースを対象に実行し、タブを移っても入力と結果はそのまま。開閉はブラウザに記憶します |
| テーマ | ヘッダーの月 / 太陽アイコンでライト / ダークを切替 |
| 個人設定 | テーマ・表示言語・表示行数・SQL の安全モード・コンソールの開閉は、セッションを永続化している場合（`SESSION_STORE=sqlite` / `redis`）アカウントに保存され、別のブラウザーでログインしても引き継がれます |
| ショートカット | `?` で一覧。`⌘/Ctrl + K` サイドバーの絞り込み、`←` `→` ページ移動、`⌘/Ctrl + Enter` SQL 実行、`Enter` セルを編集 |
| エラー | 読み込みに失敗した場合は「再試行」ボタンで再取得できます。ページ全体のエラーは再読み込みで復旧します |

| セキュリティ | いまログインしているアカウントの 2 要素認証（後述）。秘密鍵の保存先が必要なため、永続セッションストアを使う構成でのみ表示されます |

## データベース

| タブ | 内容 |
|---|---|
| 構造 | テーブル / ビューの一覧（行数の概算（「数える」で正確な行数）・エンジン・照合順序・作成 / 更新日時（MySQL）・コメント。最下行に件数と、行数・サイズの合計）、テーブル作成、「ビューを作成」（名前と SELECT 文。OR REPLACE、カラム名、WITH CHECK OPTION、MySQL は ALGORITHM / DEFINER / SQL SECURITY も）。チェックボックスで複数選択して「選択したテーブルをエクスポート」「CREATE 文を表示」「メンテナンス…」（MySQL: ANALYZE / CHECK / CHECKSUM / OPTIMIZE / REPAIR、PostgreSQL: ANALYZE / VACUUM / VACUUM FULL）「別の場所へコピー…」（同じ名前のまま別のデータベース / スキーマへ）「接頭辞を追加… / 置換…」（置換で新しい接頭辞を空にすると取り除く）「…を空にする…」「…を削除…」（1 件ならテーブル名、複数ならデータベース名の入力で確認）。一覧の下の「データ辞書」で、全テーブル / ビューのカラム（型・NULL・既定値・参照先・コメント）とインデックスを 1 ページにまとめて印刷できます |
| SQL | データベースを対象にした SQL コンソール（後述） |
| 検索 | 語を含む行を、選んだテーブルのすべてのカラムから探します。「探し方」で、語句として / いずれかの語 / すべての語（行のどこかに）/ 正規表現（サーバーの書き方）を選べ、「カラム名で絞る」で名前にその文字列を含むカラムだけに絞れます（大文字と小文字は区別しない。`%` や `_` もそのままの文字として探す。値を文字として読めないカラムは対象外で、MySQL はバイナリ・BIT・空間型、PostgreSQL は bytea と PostGIS の型。PostgreSQL の bit や point などは文字として読めるので検索する）。テーブルごとに一致した行数を表示し、「SQL タブで開く」で一致した行を取り出す SELECT を SQL タブに入れます。テーブルは 1 つずつ順に検索するので、途中で「中止する」と残りは検索しません。件数は 10 万行で打ち切り「N 行以上」と表示します。**何を一致とみなすかはサーバーで異なります**: MySQL は接続の照合順序で比べるので、`_bin` のカラムでも大文字と小文字を区別せず、アクセントも無視します。日本語ではひらがなとカタカナ、全角と半角の英数字・カタカナ、濁点の有無（ハとパ）も同じとみなすので、広めに一致します（半角カタカナの濁点付き「ﾊﾟ」は 2 文字として扱われるので、向きによって結果が変わります。全角の「パ」で探すと「ﾊﾟ」を含む行も見つかりますが、半角の「ﾊﾟ」で探しても「パ」だけの行は見つかりません）。PostgreSQL はアクセントを区別し、全角と半角も別の文字として扱います。`COLLATE "C"` のカラムでは ASCII 以外の大文字小文字も区別します |
| クエリ | テーブル・出力するカラム（別名・表示・並べ替え）・条件を選んで SELECT 文を作り、「SQL タブで開く」で編集・実行します。条件は「カラム・演算子・値」の組で、グループの中は AND、グループ同士は OR でつなぎます。値は引用符付きで SQL に書き込みます。「を含む」「で始まる」は LIKE なので、PostgreSQL では大文字と小文字を区別し、MySQL はカラムの照合順序に従います（「検索」タブとは違います）。複数のテーブルは**外部キーでつなぎます**（最初に選んだテーブルを起点に、すでに結合したテーブルへの外部キーで順に LEFT JOIN。別のデータベースやスキーマへの外部キーは使いません。同じ 2 テーブルを結ぶ外部キーが複数あるときは制約名の順で最初のものを使うので、別のキーで結合したいときは SQL タブで ON を書き換えてください）。外部キーでつながらないテーブルは、「結合」で種類（INNER / LEFT / RIGHT）とつなぐカラムを指定すれば組み合わせられます（指定しないと作成を断ります）。演算子は「検索」タブと同じです。「保存した組み立て」で、テーブル・カラム・条件・結合を名前を付けて保存し、あとで戻せます（保存先は保存済みクエリと同じ）。phpMyAdmin の自由記述の条件欄は無いので、SQL タブで書き足してください |
| デザイナ | テーブルと外部キーの図。線は外部キーを表し、箱には既定で外部キーとその参照先のカラムだけを示します（「全カラムを表示」で全カラム）。箱はドラッグ、または選択して矢印キー（Shift で大きく）で動かせ、配置はこのブラウザに保存されます（「配置を元に戻す」で自動配置に戻る）。「保存したページ」で配置に名前を付けて保存・再表示できます（アカウントに保存できる環境ではアカウントに、そうでなければこのブラウザに）。**外部キーの作成**は「図で外部キーを作る」で、付けるカラム、続けて参照先のカラム（別のテーブル）を順に選ぶと、外部キーの SQL の確認画面が開きます（ドラッグで線を引くのではなく、キーボードでも操作できる 2 回の選択です）。「外部キーを追加」からは従来どおりフォームで追加できます。**削除**は、図の下の外部キー一覧の「削除」から（SQL を確認してから実行）。「表示カラム」でテーブルごとの表示カラムを選ぶと、図に ◆ が付きます。図は「SVG で保存」でファイルに、「PDF で保存（印刷）」でブラウザの印刷画面（送信先を PDF にする）から出力できます。図の下に同じ外部キーの一覧（参照先・ON DELETE / ON UPDATE・制約名）を表で示し、別のデータベースやスキーマを参照する外部キーは、一覧にだけ参照先を修飾名で示して図には線を引きません。phpMyAdmin のデザイナと違い、図の上でテーブルを作ったり変えたりはできません |
| エクスポート | データベース全体を SQL / CSV / JSON / XML / YAML / Markdown / LaTeX / Texy! / MediaWiki / HTML / ODS / ODT / DOCX でダウンロード（対象テーブルを選択可）。詳細は下の「エクスポートの詳細」 |
| インポート | SQL スクリプト（mysqldump / mariadb-dump / pg_dump）、CSV、ODS、XML、MediaWiki の表を投入。gzip・zip 圧縮のままでも、Shift_JIS などの文字コードでも取り込めます。進捗表示と中止ができます。詳細は下の「インポートの詳細」 |
| 権限 | このデータベースに対する各ユーザーの現在の権限（すべて / 一部 / なし）と、DB 単位の GRANT / REVOKE ALL。「権限を選ぶ…」で `SELECT` / `INSERT` / `UPDATE` / `DELETE` / `REFERENCES` / `TRIGGER` と対象（データベース全体か 1 テーブル）を指定して付与・取り消しできます（両方の DB で同じ意味を持つ権限のみ。MySQL の `INDEX`、PostgreSQL の `TRUNCATE` などは SQL タブで）。テーブルを選ぶとカラムを絞れます（`SELECT` / `INSERT` / `UPDATE` / `REFERENCES` のみ。`DELETE` と `TRIGGER` はテーブル単位だけで、カラムと同時に選ぶと実行前に止まります）。カラム単位の取り消しはカラム単位の権限にだけ効き、テーブル全体の権限は狭まりません（テーブル全体の権限は全カラムを含みます）。サーバー全体（`*.*`）の権限で許可されているユーザーには「グローバル」バッジが付きます（このデータベースでの取り消しでは外れません） |
| ルーチン | ストアドプロシージャ / 関数。「定義を表示」で CREATE 文を取得し、「SQL タブで編集」「SQL をダウンロード」ができる。行の「実行」は引数の値（NULL も可）を入れて CALL / SELECT を SQL タブに用意する（MySQL の OUT / INOUT はユーザー変数で受けて SELECT する。実行は SQL タブで確認してから）。「特性を変更」でセキュリティ・データアクセス（MySQL）・コメントだけを変更、「削除」で DROP。下の「ルーチンを作成」で種類・名前・引数・戻り値の型・本体・DEFINER / SQL SECURITY / データアクセスから作成（MySQL の BEGIN … END は途中の `;` ごとそのまま書けます。DELIMITER は不要） |
| トリガー | トリガー一覧と定義（「SQL タブで編集」「SQL をダウンロード」「削除」）。「トリガーを作成」で対象テーブル・タイミング・イベント・本体・DEFINER（MySQL）から作成（PostgreSQL ではトリガー関数「名前_fn」も一緒に作ります） |
| イベント | MySQL のイベントスケジューラ（有効化 / 無効化 / 削除、定義の「SQL タブで編集」「SQL をダウンロード」、「イベントを作成」で 1 回だけ / 繰り返しのスケジュール・ON COMPLETION PRESERVE・DEFINER から作成）。PostgreSQL では非対応の旨を表示 |
| セントラルカラム | このデータベースで繰り返し使うカラムの定義（名前・型・NULL・既定値・コメント）を保存します。手で追加するか、既存のテーブルから取り込みます。構造タブの「カラムを追加」で「セントラルカラムから入力」を選ぶと、その定義から始められます。保存先は保存済みクエリと同じです |
| 操作 | データベースの**名前変更**と**コピー**（下の「データベースの名前変更とコピー」） |

### データベースの名前変更とコピー

どちらも SQL を確認してから実行します。サーバー自身のデータベースは対象外です。「既定の照合順序を変更」は、接続中のデータベースにも使えます（MySQL は既定の照合順序と、選べば全テーブル・全カラムの変換。PostgreSQL はデータベースの照合順序があとから変えられないため、このスキーマの全文字列カラムへの照合順序の付与だけ）。PostgreSQL では、ログイン時に指定したデータベース（このセッションの接続先）も対象外です。

| | MySQL | PostgreSQL |
|---|---|---|
| 名前変更のしくみ | 名前変更の命令がないため、新しいデータベースを作り、全テーブルを 1 文（原子的）で移します。**元のデータベースは削除しません**。あなたのアカウントから見えないルーチン・イベントや、確認の後に作られたテーブルを巻き込まないためです。テーブルが見えなくても空とは限らないので、削除するならすべてを見られる管理者のアカウントで中身を確かめてから。古い名前のままのアプリが起動時にテーブルを作る設定だと、元のデータベースに書き込み続ける点にも注意してください | `ALTER DATABASE … RENAME TO` |
| 名前変更できないとき | ビュー・ルーチン・トリガー・イベントが 1 つでもある（移せずに元へ取り残され、ビューは移ったテーブルを参照できなくなるため、実行前に止めます） | 実行中の処理がある |
| 名前変更で引き継がれないもの | データベースに付けた権限（GRANT） | なし |
| 確認 | 元のデータベース名の入力が必要 | 元のデータベース名の入力が必要 |
| コピーされるもの | テーブルの構造と（選べば）データ。選べば、外部キー（コピー側のテーブルを指す）、次の AUTO_INCREMENT 値、このデータベースに付けたアカウントの権限（GRANT）も。ビュー・ルーチン・トリガー・イベントはコピーされません | データベース全体（テーブル・ビュー・関数・データ）。他の利用者が元に接続していると失敗します |

PostgreSQL では、実行前にそのデータベースへの tsmyadmin の**待機中の**接続（同じ DB アカウントのもの）を切断します。実行中の処理は切断せず、その場合は変更されずに失敗します。コピーには元のデータベースの所有者かスーパーユーザーの権限が必要です。

## テーブル

### 表示（ブラウズ）

- カラム見出しをクリックでソート（昇順 → 降順 → 解除）。Shift + クリックで複数カラム（番号が並べ替え順）。「表示行数」はブラウザに記憶されます
- 「カラム N/M」で表示するカラムと並び順（矢印で左右へ）を選択。URL に入り、テーブルごとにブラウザーが覚えます
- 「キーで並べ替え」で、インデックスの順（昇順 / 降順）に並べ替えられます
- 「表示のしかた」で、長い値を全文で表示、外部キーの参照先の名前を併記（参照先のテーブルの最初の文字列カラム）、バイナリを 16 進で表示（先頭 256 バイト）、空間データを WKT で表示（MySQL の空間型と PostGIS）に切り替えられます（ブラウザーが覚えます）
- 画面には値の先頭だけが届きます（バイナリは 64 KB、長いテキストも途中まで）。行を特定できるテーブルでは、そうした値の横の「ダウンロード」で全体を取り出せます（64 MB まで）
- 外部キーの値には参照先へのリンク（↗）、主キーには参照元テーブルへのリンク（↵）が付きます
- 絞り込みなしで 10 万行を超えるテーブルは全件カウントを省略し「約 N 行（概算）」を表示します
- **編集**: 行頭の鉛筆でダイアログ編集、セルのダブルクリックでインライン編集（`Enter` で保存 / `Esc` でキャンセル）。コピーアイコンで **行を複製**（自動採番カラムは新しい値）
- **削除**: 行頭のごみ箱でその行だけ、またはチェックボックスで選択して「選択行を削除」。確認ダイアログの後に削除されます
- **選択した行**: 「選択行を編集」で選んだ行をまとめて編集します（行ごとに変えた列だけを更新。1 行ずつ実行し、失敗したらそこで止めます）。「選択行を CSV で / JSON で」「選択行をコピー」も使えます（途中で切った値を含む行はエクスポートタブで）。「このページのグラフ」は表示中の行をグラフにします
- 空間データのカラム（MySQL の GEOMETRY 系、PostgreSQL の point / polygon などと PostGIS の geometry / geography）があるテーブルでは、表の下の「図形で表示（GIS）」で、そのページの値を座標どおりの縮尺で描きます。背景の地図はなく、外部のサービスにも問い合わせません
- 表の上に、そのページを取得した SQL と所要時間を表示します。条件の値は SQL に埋め込まず、「バインドした値」として並べます
- 主キーもユニークキーもないテーブルは、PostgreSQL では `ctid`、MySQL では全カラム一致（バイト単位の比較。照合順序が同じと見なす大文字小文字やアクセント違いの行は別の行として扱います）で 1 行だけを特定します。該当行が 1 件でない場合は変更せずにエラーになります。`ctid` は物理位置なので、他のセッションがその行を更新・削除した後は古い画面からの編集が別の行に当たる可能性があります — 主キーのないテーブルを編集するときは直前に再読み込みしてください（主キーを付けるのが根本対策です）
- ビューとシーケンスは読み取り専用です。PostgreSQL のパーティション親テーブル・継承の親テーブルも編集できません（`ctid` が子ごとに重複して行を特定できないため。子テーブル側で編集してください）

### 構造

- カラムの追加・変更・削除、インデックスの追加・削除、外部キーの追加・削除（MySQL は別のデータベースの、PostgreSQL は同じデータベースの別のスキーマのテーブルも参照できます）、参照元の表示、CREATE 文の表示
- カラムの追加・変更では、照合順序、MySQL の属性（UNSIGNED / ZEROFILL / BINARY）と「更新時に CURRENT_TIMESTAMP を入れる」、**生成カラム**（式と STORED / VIRTUAL）、位置（MySQL: 先頭 / 指定したカラムの後）、追加と同時に付けるキー（PRIMARY / UNIQUE / INDEX）を指定できます。PostgreSQL は位置を変えられず、既存のカラムを生成カラムにすることや STORED と VIRTUAL の切り替えはできません（式の変更は PostgreSQL 17 以降）
- カラムの左のチェックで選び、表の下のボタンで、選んだカラムに主キー（既存の主キーは置き換え）/ ユニーク / インデックス（MySQL は全文 / 空間も）を付ける、**まとめて変更**（1 カラムずつフォームを進め、最後に 1 つの SQL で確認）、**まとめて削除**できます。MySQL は「カラムを並べ替え…」で全カラムの順番を変えられます（PostgreSQL は列の順番を変えられません）
- インデックスは種類（MySQL: 全文 / 空間を含む）、方式（MySQL: BTREE / HASH、PostgreSQL: BTREE / HASH / GIN / GiST / BRIN / SP-GiST）、MySQL のプレフィックス長（先頭何文字を索引にするか）を指定でき、あとから**名前の変更**と**変更**（削除と作成を 1 つの確認で）ができます
- 「参照元」の「表示カラム」で、このテーブルの行を名前として示すカラムを選べます。表示タブの「外部キーの参照先の名前を併記」で使われます（既定は最初の文字列カラム。ブラウザーが覚えます）
- 「パーティション」: パーティションの一覧（範囲 / 値・行数・容量）と、追加・空にする・削除・保守（MySQL: ANALYZE / CHECK / OPTIMIZE / REBUILD / REPAIR、PostgreSQL: ANALYZE）。範囲は名前の後に続く部分をサーバーの書き方どおりに書きます（MySQL `VALUES LESS THAN (100)`、PostgreSQL `FOR VALUES FROM (0) TO (100)` / `DEFAULT`）。MySQL は既存のテーブルを「パーティションに分割…」（RANGE / LIST / HASH / KEY）でき、「パーティション分割を解除」で 1 つのテーブルに戻せます。PostgreSQL は既存のテーブルを分割できないため、データベースの「テーブルを作成」で「パーティション分割」を選んで作り、パーティションを追加します。PostgreSQL ではパーティションを「切り離す」（行を持ったまま独立したテーブルにする）こともできます
- 「容量と行の統計」: データ・インデックス・空き（MySQL。OPTIMIZE で回収できる分）・TOAST（PostgreSQL）の容量、行数（概算）、平均の行サイズ、行フォーマット・作成 / 更新日時（MySQL）、不要な行・最終 VACUUM / ANALYZE（PostgreSQL）。値はサーバーのカタログのものです。「この構造を印刷」で、ヘッダーやサイドバーを除いた構造を印刷できます
- 変更はすべて **生成 SQL のプレビュー → 「実行する」** の順に進みます。TRUNCATE / DROP など元に戻せない操作はオブジェクト名の再入力が必要です
- 「表示の変換」で、表示タブでのカラムの見せ方を変えられます（バイナリを画像として、値をリンクとして、JSON を整形して。値そのものは変わりません）。リンクは http / https だけで、「リンク先」に `{value}` を書くと値を URL エンコードして差し込みます。保存先は保存済みクエリと同じです
- 下の「正規化の手がかり」は、定義と先頭 500 行から第 1〜第 3 正規形に反していそうな箇所（主キーがない、番号付きの列、区切り文字で並べた値、外部キーのない参照、主キーの一部や主キー以外の列で決まる列）を挙げます。値から読む依存関係は推定です。挙げるだけではテーブルを変更しません。主キー以外のカラムで決まるカラムの組や、番号付きの繰り返しカラム（主キーがあるとき）には「新しいテーブルに分ける…」が付き、新しいテーブル名・移すカラム・元から削除するかを選んで SQL を確認できます（依存関係は新しいテーブルの主キー追加で全行に対して確かめられ、合わなければそこで止まって元のテーブルは変わりません）

### SQL

- `⌘/Ctrl + Enter` で実行。複数文は文ごとに結果（行 / 影響行数 / エラー位置）を表示し、完了した文から順に描画されます
- 実行中は「キャンセル」で中断できます。「最大行数」を超えた結果は先頭だけを表示します（切り詰めの表示あり）
- 「EXPLAIN」で 1 文の実行計画を表示
- 「整形」は文を節ごとに改行して読みやすくします（語の大文字・小文字と、文字列・識別子・コメントの中身は変えません）
- 「実行のオプション」: **区切り文字**（MySQL。`DELIMITER` の指定欄。ルーチンの本体に `;` を含めるとき）、**終了時にロールバック**（`START TRANSACTION` / `BEGIN` から始めて、終わりにサーバーが戻します。MySQL の定義変更のように暗黙にコミットされる文は戻りません）、**外部キーを検査する**（オフで `FOREIGN_KEY_CHECKS = 0`、PostgreSQL は `session_replication_role = replica`。この実行の間だけ）。文に `:名前` があると**パラメーター**の入力欄が出て、値は数値ならそのまま、それ以外は引用符つきの文字列（NULL も選べる）として文に埋め込まれます。追加した文は結果の先頭に通常の文として並びます
- 「プロファイリング」（MySQL / MariaDB）: 文ごとに、サーバーが各段階で使った時間を表示します（`SHOW PROFILE`）。PostgreSQL には段階ごとの計測がないため、実行計画と時間は `EXPLAIN ANALYZE` で見てください
- 「WHERE のない UPDATE / DELETE を確認」（既定でオン）: 全行が対象になる文を実行する前に確認します。入力されたテキストを読んで判断するため、確認が多めに出ることはありますが、見落とすことはありません。チェックを外すと確認なしで実行します
- 結果は「CSV」「JSON」で画面に表示されている分をダウンロードできます。CSV には「表計算ソフトで数式として実行されないようにする」を付けられます（既定はオフ。値の先頭にアポストロフィが付くため、そのファイルをインポートで戻す用途では使わないでください）
- 「コピー」は結果をタブ区切り（先頭行はカラム名、NULL は `NULL`）でクリップボードに入れます（「表計算ソフトで数式として実行されないようにする」はコピーにも効きます）。表計算ソフトに貼るとセルに分かれます。HTTPS でも localhost でもない接続では、ブラウザによってコピーできないことがあります（その場合は失敗したと表示します）。表示を切り詰めた値を含む結果は、ダウンロードと同じくコピーできません
- 「印刷」はその文の結果だけを印刷します（エディタ・サイドバー・タブは印刷しません）。画面では一部の行だけを描いている長い結果も、印刷では先頭 1,000 行まで並べます。ブラウザの印刷（`⌘/Ctrl + P`）では、すべての結果を印刷します
- SELECT の結果の下の「この SELECT からビューを作成」で、その文を入れた「ビューを作成」フォームがデータベースの構造タブに開きます
- 「グラフ」は結果を棒グラフか折れ線グラフで表示します。項目（横軸）に 1 カラム、値（縦軸）に数値のカラムを最大 6 つ選びます。値に選べるのは、NULL でない値が 1 つ以上あり、それがすべて数値のカラムです（数値でない値が 1 つでもあれば選べません）。値が NULL の行はその系列から外れます（折れ線は途切れます）。描くのは先頭 500 行までで、円グラフなど他の種類はありません
- 「保存済みクエリ」に名前を付けて保存（最大 200 件）。保存先は運用形態によって変わり、パネルに表示されます。セッションを永続化している場合（`SESSION_STORE=sqlite`。本番の既定）は接続ユーザーのアカウントに紐づけて暗号化して保存され、別のブラウザーからログインしても同じ一覧が見えます。`SESSION_STORE=memory` の場合はこのブラウザーにのみ保存されます。
- 「履歴」は直近 100 件（「履歴をクリア」で削除できます。共有端末では離席前に消してください）。入力途中の SQL はタブを移動しても保持されます（このブラウザタブ内）

各実行は自動コミットです。`BEGIN` を発行したまま終了したスクリプトは、接続を返却する前にロールバックされます（その場合は「トランザクションが開いたままだったため取り消しました」と表示されます）。`BEGIN` と `COMMIT` は同じ実行に入れてください。

|---|---|
| 検索 | カラムごとの条件（=, ≠, <, >, 「を含む」「で始まる」（ワイルドカード不要）, LIKE, IN, BETWEEN, REGEXP, 空文字, IS NULL …）を組み合わせて絞り込み。IN は値をカンマで区切り、BETWEEN は「下限, 上限」。REGEXP はサーバーの正規表現で、MySQL はカラムの照合順序に従います（大文字と小文字を区別しないことがある）。結果は「表示」タブに引き継がれます。「オプション」で表示するカラム・並べ替え・1 ページの行数を選べ、**DISTINCT** や **SQL で書いた条件**（WHERE 句の本文。上の条件と AND）を使うと、SELECT 文を SQL タブで開きます。下の「ズーム検索」は、数値のカラムを 2 つ選ぶと検索条件に合う行を散布図にし、点を選ぶとその行を開けます（主キーのあるテーブル）。軸ごとに最小・最大で範囲を絞れ、ラベルのカラムを選ぶと点に値が付き、描く行数の上限は 100 / 500 / 1,000 から選べます（既定 500）。「検索して置換」は、文字列のカラム 1 つについて、一致するすべての行の文字列を置き換えます（「正規表現として扱う」で正規表現も。後方参照は MySQL 8 が `$1`、MariaDB と PostgreSQL が `\1`。通常は大文字と小文字を区別し、実際に値が変わる行だけを更新。SQL を確認してから実行。元に戻せません） |
| 挿入 | フォームで行を挿入（「一度に入れる行数」で最大 10 行。何も入力しなかった行は挿入しません。1 行ずつ実行し、失敗したらそこで止めて、それまでの件数を表示）。カラムごとに「既定値を使う」「NULL」、**関数**（NOW / CURRENT_DATE / CURRENT_TIME / UUID / MD5 / SHA1 / SHA-256 / UPPER / LOWER / TRIM。値を受け取るものは入力欄の値が引数。PostgreSQL に SHA1 はありません）を指定できます。外部キーのカラムには参照先の値（先頭 200 件）が候補に出ます。バイナリのカラムは「ファイルから」で 512 KB までのファイルを入れられます（編集でも差し替え可）。挿入後もこの画面に留まり、続けて入力できます（「一覧へ戻る」で表示へ） |
| エクスポート | このテーブルをダウンロード（形式・構造 / データ・オプションはデータベースのエクスポートと同じ） |
| インポート | このテーブルへ CSV / ODS / XML / MediaWiki の表（または SQL）を投入 |
| トリガー | このテーブルのトリガー。「トリガーを作成」はこのテーブルを対象にします |
| 権限 | ログインできるアカウントごとに、このテーブルへの SELECT / INSERT / UPDATE / DELETE / REFERENCES / TRIGGER と、その出どころ（テーブル・カラム・データベース全体・サーバー全体。PostgreSQL はスーパーユーザー）を表示します。「権限を選ぶ…」はこのテーブルを対象に選んだ状態で開きます。ここでの取り消しはテーブルとカラム単位の権限にだけ効き、データベース全体やサーバー全体の権限は残ります。ロール経由で得ている権限は表示しません（PostgreSQL ではテーブル所有者の暗黙の権限と PUBLIC の権限も）。MySQL の部分的な取り消し（`partial_revokes`）は反映します |
| 追跡 | テーブルの定義（CREATE 文）を、記録した時点のバージョンとして残し、2 つのバージョン（または現在の構造）の違いを行単位で表示します。記録は「現在の構造を記録」で行い、自動では記録しません。どこから変更されても最新のバージョンとの違いとして表れます。「記録する文の種類」で選んだ種類の文（CREATE / ALTER / RENAME / DROP / TRUNCATE / INDEX、INSERT / UPDATE / DELETE。既定は定義の変更だけ）のうち、このツールから実行したものを「記録された文」に残します（ほかのクライアントからの変更はバージョンの違いとしてだけ表れます）。表の編集からの行の変更は、値を除いて「何行・どのカラム」だけを残します。記録された文は行の値を含むことがあるため、そのテーブルの行を読めるアカウントにだけ表示します。文は 16 KB まで、記録はサーバー全体で 2,000 件までです。データベースの「追跡」タブに、追跡しているテーブルの一覧があります。定義は 64 KB まで、バージョンはサーバー全体で 2,000 個までで、超えると古いバージョンから消えます。サーバーの全アカウントで共有し、セッションを永続化している場合だけ表示されます |
| 操作 | 「テーブル名を変更」、「テーブルオプション」（コメント。MySQL はエンジン・照合順序・次の AUTO_INCREMENT 値・行フォーマット・CHECKSUM も）、「全カラムの照合順序を変更」（MySQL は表の既定と全文字列カラムを CONVERT TO、PostgreSQL は全文字列カラムに COLLATE）、「行の並び順を変更」（MySQL: ALTER TABLE … ORDER BY、PostgreSQL: インデックスに沿った CLUSTER）、「テーブルを移動」（同じ名前のまま行ごと。MySQL は別のデータベースへ、PostgreSQL はこのデータベースの別スキーマへ。移動後は移動先のページに切り替わります）、「テーブルをコピー」（コピー先のデータベース（MySQL）/ スキーマ（PostgreSQL）、構造とデータ / 構造のみ / データのみ、同じ名前のテーブルを削除してから作る（名前の再入力が必要）、外部キーもコピー）、「メンテナンス」（MySQL: ANALYZE / OPTIMIZE / CHECK / REPAIR / CHECKSUM / FLUSH TABLE、PostgreSQL: ANALYZE / VACUUM / VACUUM FULL）、「テーブルを空にする…」（TRUNCATE）、「テーブルを削除…」（DROP）。ビューでは「ビューの定義を変更」（現在の定義を読み戻して CREATE OR REPLACE。ALGORITHM / DEFINER / SQL SECURITY / CHECK OPTION も）と「ビューを削除…」 |

### エクスポートの詳細

- 形式は SQL・CSV・CSV（Excel 用）・JSON・XML・YAML・Markdown（表）・LaTeX・Texy!・MediaWiki・HTML・ODS・ODT・DOCX。CSV は 1 テーブルずつ（「テーブルごとに別のファイルにする」を選ぶとテーブルごとの CSV を zip に）で、区切り文字をカンマ・セミコロン・タブから選べます。「CSV（Excel 用）」はセミコロン区切りで UTF-8 BOM 付きです。XML と YAML は値を失いません（NULL・バイナリ（base64）・XML に書けない制御文字を含む文字列（base64）を区別します）。Markdown・LaTeX・Texy!・MediaWiki・HTML は文書に貼るための表で、バイナリ値は大きさだけを書きます。ODS（スプレッドシート）・ODT・DOCX は読む・共有するためのファイルで、NULL は空のセルになります（ODS はインポートで戻せます）
- **PDF は直接は作りません**（日本語などのフォントを PDF に埋め込むにはフォントの同梱が必要なため）。「HTML（印刷 / PDF 用）」をブラウザーで開いて印刷し、送信先を「PDF に保存」にしてください
- **出力**: 「飛ばす行数」「出力する行数」（各テーブルの先頭から数えます。どの形式でも使えます）、圧縮（gzip / zip）、「テーブルごとに別のファイルにする」（zip にまとめます）、ファイル名のテンプレート（`@DATABASE@` `@TABLE@` `@SERVER@` と日時 `%Y %m %d %H %M %S`。拡張子は付きます）、文字コード（UTF-8、Shift_JIS（CP932）、EUC-JP、ISO-8859-1、Windows-1252、GBK、Big5、EUC-KR。その文字コードで表せない文字があると、値を `?` に変えずにエクスポートを止めます。JSON・XML・YAML・HTML は自身が UTF-8 と宣言する形式なので、常に UTF-8 です）。テーブルごとに別のファイルにするときは、ファイル名のテンプレートに `@TABLE@`（サーバー全体では `@DATABASE@`）がなくても、名前にテーブル（データベース）名が付いて重ならないようにします。書き出しは順に流すため、大きなテーブルでもサーバーのメモリに全体を持ちません
- **SQL のオプション**: 文の種類（INSERT / UPDATE / REPLACE。UPDATE と REPLACE はすべてのテーブルに主キーが必要で、PostgreSQL の REPLACE は `ON CONFLICT … DO UPDATE`）、INSERT にカラム名を含める、1 つの INSERT に複数行を入れる（1 文の最大長を指定でき、0 は行のまとまりごとに 1 文）、`INSERT IGNORE`（PostgreSQL は `ON CONFLICT DO NOTHING`）、`CREATE TABLE IF NOT EXISTS`、`CREATE DATABASE IF NOT EXISTS` と `USE`（PostgreSQL は `CREATE SCHEMA`）、ビューをテーブルとして出力（カラムと行）、コメントと見出し、全体を 1 つのトランザクションにする、時刻を UTC で出力する（セッションも UTC に）、テーブルごとの `LOCK TABLES … WRITE`（MySQL）。バイナリ値は常に 16 進で書き出します
- 「エクスポートのテンプレート」に、今の選択（対象テーブル・形式・構造 / データ・DROP・BOM など）を名前を付けて保存し、後で呼び出せます。データベース（PostgreSQL はスキーマ）ごとの一覧で、テーブル単位のエクスポートタブにはありません。保存先は「保存済みクエリ」と同じで、セッションを永続化していれば接続ユーザーのアカウント（暗号化して保存、別のブラウザーからも見える）、そうでなければこのブラウザーです。アカウントに保存する場合、保存件数の上限（200 件）は保存済みクエリと共有します（ブラウザーに保存する場合はそれぞれ 200 件）。読み込んだときに無くなっているテーブルは選択から外し、名前を表示します
- SQL にはルーチン・トリガー・イベントも含められます。ルーチンの区切りは `DELIMITER ;;` です
- MySQL では `DEFINER` 句（ルーチン・トリガー・イベント）を除いて別ユーザーで復元できます
- MySQL の SQL ダンプはデータベース名を含まないため、別名のデータベースへそのままインポートできます
- MariaDB の SEQUENCE は `CREATE SEQUENCE` と現在値からの `RESTART`、PACKAGE は仕様と本体の順に出力されます
- PostgreSQL の `serial` / `bigserial` カラムは `GENERATED BY DEFAULT AS IDENTITY`（identity カラム）として出力されます。採番の挙動は同じですが、復元後は専用のシーケンスが別オブジェクトとして存在しなくなるため、`nextval('テーブル名_id_seq')` を名指しするアプリケーションやトリガーがある場合は復元先で修正が必要です
- PostgreSQL の独立したシーケンス（serial / identity カラムの内部シーケンス以外）は `CREATE SEQUENCE`・`OWNED BY`・現在値（`setval`）として出力されます
- PostgreSQL のマテリアライズドビューは `WITH NO DATA` で作成した後に `REFRESH MATERIALIZED VIEW` されます
- PostgreSQL では制約（CHECK / UNIQUE / EXCLUDE / 外部キーのオプション）、カラムの照合順序、identity カラムのオプション、`UNLOGGED`、継承・パーティション、マテリアライズドビューのインデックス、トリガーの有効状態も復元されます
- 「DROP TABLE IF EXISTS を付ける」は、PostgreSQL ではダンプに含まれるオブジェクトの DROP を依存順にまとめて先頭に出力します（`CASCADE` は使わないため、ダンプ外のオブジェクトが依存している場合は復元がそこで止まります）。MySQL では各 CREATE の直前に出力します
- ビュー・ルーチンはサーバーのカタログに基づく依存順で並びます

### インポートの詳細

- ファイルは gzip（`.gz`）・zip で圧縮したままでも取り込めます（zip は中のファイルが 1 つのとき。SQL は複数のファイルを名前順にまとめて実行できます。展開後は最大 256 MB）。文字コードは既定が UTF-8 で、Shift_JIS（CP932）・EUC-JP などを選べます（読めないバイトがあるときは、文字を置き換えずに取り込みを止めます）。ファイルはファイル選択のほか、入力欄へのドラッグ & ドロップでも選べ、拡張子（`.sql` `.csv` `.ods` `.xml`）から形式を選びます。mysqldump には `--hex-blob` を付けてください。psql のメタコマンド（`\connect` など、`pg_dump -C` の出力）は実行できません
- 「先頭から飛ばす件数」で、SQL は最初の N 文、そのほかの形式は最初の N 行を飛ばして、前回途中で止まった続きから取り込めます（SQL では、飛ばす範囲にある `USE` と `SET` は、あとの文が頼るので実行します）
- SQL では「エラーで停止」（既定オン。オフにすると失敗した文を飛ばして続行）、「外部キー制約のチェックを無効にする」、「1 つのトランザクションで実行する」を選べます
- **「1 つのトランザクションで実行する」は MySQL では全体の取り消しを保証できません**。`CREATE` / `DROP` / `ALTER` が暗黙のコミットを起こすため、構造を含むダンプでは「最後のコミット以降」だけが取り消されます（その場合は「一部が反映されています」と表示されます）
- **PostgreSQL の「外部キー制約のチェックを無効にする」はスーパーユーザー権限が必要**です。権限がない場合は `OPTION_FAILED` を表示して取り込みを中止します（ファイルの文は 1 つも実行されません。オプションを外して再実行してください）
- CSV・ODS・XML・MediaWiki の表は、全行を 1 つのトランザクションで取り込み、途中でエラーになるとファイル全体を取り消します（取り込みは中止できません）。「取り込み先テーブル」を選ぶか、「ファイルの内容からテーブルを作って取り込む」を選んで新しいテーブル名を入力します（カラム名はファイルの見出し、型は値から推定します。整数・小数・日付・日時・文字列に収まる大きさの型で、あとから構造タブで直せます。データベースのインポートタブだけで、テーブル単位のタブでは使えません）。「主キー・一意キーが重複した行」は、エラーにする（既定）・飛ばす・置き換える（MySQL は「飛ばす」が `INSERT IGNORE`（重複以外のエラー、たとえば値の切り詰めも警告になって黙って通ります。挿入した行数は実際に入った行だけを数えます）、「置き換える」が `REPLACE`（削除と挿入なので、`ON DELETE CASCADE` の子の行も消えます）。PostgreSQL は `ON CONFLICT`）から選びます。テーブルを作った取り込みが途中で失敗したときは、作ったテーブルを削除して戻します
- CSV は「区切り文字」「囲み文字」「エスケープ文字」（囲み文字と同じなら二重化）「1 行目をカラム名として扱う」「NULL を表す値」（既定 `\N`）を指定します。空のフィールドは空文字列として取り込まれ、引用符で囲まれていない値が NULL 表記と一致したときだけ NULL になります。ヘッダー名の大文字小文字は区別しません
- ODS はこのツールや LibreOffice・Excel が書いたスプレッドシートで、1 行目をカラム名として読み、空のセルは NULL、数式は計算された値を取り込みます。XML はこのツールまたは phpMyAdmin のエクスポート、MediaWiki は `{| … |}` の表です。1 つのファイルに複数のシート / 表があるときは「シート / 表」に名前か番号を入れます（空欄は最初の 1 つ）
- SQL の「AUTO_INCREMENT 列の 0 をそのまま入れる」（MySQL の `NO_AUTO_VALUE_ON_ZERO`）は、0 を採番のきっかけにせず値として入れます（他のサーバーから戻すダンプ向け）
- 結果には実行・成功・失敗・未実行の文数、エラーの行番号、データベースを切り替えた / トランザクションを取り消した警告が出ます

## 設定

画面上部の「設定」で、次を選べます。値はこのブラウザーに保存され、セッションを永続化している環境では接続しているアカウントにも保存されて、別のブラウザーへ引き継がれます（言語とテーマは画面上部のスイッチで切り替えます）。保存すると画面を読み込み直して反映します。

| 区分 | 設定 |
|---|---|
| メインパネル | 表の 1 ページの行数 |
| SQL | セーフモード、SQL コンソールの常駐、履歴に残す件数（サーバーごと、10〜1,000） |
| ナビゲーション | テーブル名をまとめる区切り（例: `_` にすると `shop_orders` と `shop_items` がサイドバーの「shop」の下にまとまる。1 つしかない接頭辞はまとめません。空欄はまとめない）、一度に出す件数（超えた分は「さらに表示」。既定の 0 はすべて）、サイドバーに出さないデータベース（サーバーのデータベース一覧からは開けます。いま開いているデータベースは隠れません） |
| エクスポート / インポートの既定値 | エクスポート画面とインポート画面が最初に選んでいる値（形式・オプション・文字コード・CSV の区切りなど） |

「設定をファイルに保存」で JSON ファイルにでき、「設定ファイルを読み込む」で別のブラウザーやサーバーへ持っていけます（読み込んだ内容は「保存する」を押すまで反映されません）。「既定に戻す」は、この画面の設定をすべて選ぶ前の状態に戻します。

## 制限事項

- 1 ページの表示は最大 1,000 行、SQL コンソールの結果は最大 10,000 行
- SQL コンソールの 1 文は 30 秒でタイムアウトします（画面から変更できません）。時間のかかる一括処理はインポート（最大 10 分）を使ってください
- 生成カラム（サーバーが他のカラムから計算する値）は挿入・編集の対象外です。構造タブからも変更できません（フォームは生成式を表現できず、MySQL ではそのまま普通のカラムになってしまうため）。SQL タブの `ALTER TABLE` を使ってください
- MySQL のカラム変更は `MODIFY COLUMN` でカラム定義を置き換えます。フォームが扱う項目（名前・型・NULL 許可・既定値・AUTO_INCREMENT・コメント）と、フォームには出ないが引き継ぐ項目（照合順序・`ON UPDATE CURRENT_TIMESTAMP`）以外は再指定されません。`INVISIBLE` と空間カラムの `SRID` は失われます。また、MariaDB では絵文字など BMP 外の文字を含む既定値がカタログで `?` になるため、カラムを編集するとその文字が `?` に変わります（MySQL では復元されます）。バイナリカラムの既定値も、サーバーのカタログが値をそのまま返さない場合があります。MySQL では NUL バイトを含む既定値（`BINARY(2) DEFAULT 0x0000` など）が途中で切れるため変更するとエラーになり、MariaDB 10.11 では接続文字セットで表せないバイト（`DEFAULT 0xFF` など）が `?` として返るため変更すると既定値が `?` に変わります。これらを持つカラムは SQL タブの `ALTER TABLE` で変更してください
- 65,536 文字を超えるテキストは先頭だけを表示し「（全 N 文字のうち先頭のみ表示）」を添えます（そのセルは画面から編集できません。SQL コンソールで更新してください。エクスポートには全文が入ります）
- 絞り込みありの件数は 100,000 行で数え止め「100,000 行以上」と表示します（最終ページへのジャンプは使えず、「次へ」で進みます）
- エクスポートで選択したテーブル名が URL に収まらない場合（数百テーブル）は案内が出ます。すべてのテーブルを選ぶか選択を減らしてください
- インポートファイルは 64 MB まで
- 「DROP TABLE IF EXISTS を付ける」（PostgreSQL）の DROP 部分は 1 つのトランザクションにまとまっていますが、復元するクライアントがエラーで止まらない設定（`psql` の既定）だと、ダンプ外のオブジェクトが依存していて DROP が失敗した後も INSERT が続き、行が重複することがあります。復元は「エラーで停止」（`psql -v ON_ERROR_STOP=1`、tsmyadmin のインポートでは既定）で行ってください
- PostgreSQL にはイベントスケジューラがありません（`pg_cron` などの拡張をご利用ください）
- ルーチン・トリガーの一覧と定義を表示し、「SQL タブで編集」で定義を置き換えるスクリプトをエディタに読み込めます（実行前に内容を確認してください）。新規作成は SQL タブで行います
