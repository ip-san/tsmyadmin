# ユーザーガイド

tsmyadmin の画面と操作の説明です。画面構成は phpMyAdmin と同じ 3 階層（**サーバー → データベース → テーブル**）で、左のサイドバーからどの階層にも移動できます。

## 接続（ログイン）

1. 「接続先」で管理者が用意したプリセットを選ぶか、「手動で入力」でサーバー種別・ホスト・ポートを入力します
2. ユーザー名とパスワードを入力して「接続する」。PostgreSQL は接続先データベース名が必要です（省略時は `postgres`）
3. 資格情報はサーバー側のセッションに保持され、ブラウザには署名付きセッション ID の Cookie が置かれます（それとは別に、前回の接続先・ユーザー名・データベース名を localStorage に記憶します。パスワードは記憶しません。共用の端末では他の人に接続先が見えることに注意してください）。無操作が `SESSION_TTL_MINUTES`（既定 30 分）続くと切断され、再接続後は元の画面に戻ります

接続できるホストは管理者が `TSMYADMIN_ALLOWED_HOSTS` で制限しています。一覧にないホストへは接続できません。

## 画面の共通要素

| 要素 | 説明 |
|---|---|
| サイドバー | データベース → （PostgreSQL はスキーマ →）テーブルのツリー。上部の入力欄でテーブル名を絞り込めます。ヘッダー左端のボタンか `⌘/Ctrl + B` で表示 / 非表示（設定はブラウザに記憶） |
| タブ | 階層ごとの機能（表示 / 構造 / SQL / …）。URL に状態が入るので、ページをそのまま共有・ブックマークできます |
| テーマ | ヘッダーの月 / 太陽アイコンでライト / ダークを切替 |
| ショートカット | `?` で一覧。`⌘/Ctrl + K` サイドバーの絞り込み、`←` `→` ページ移動、`⌘/Ctrl + Enter` SQL 実行 |
| エラー | 読み込みに失敗した場合は「再試行」ボタンで再取得できます。ページ全体のエラーは再読み込みで復旧します |

## サーバー

| タブ | 内容 |
|---|---|
| データベース | 一覧（サイズ、MySQL はテーブル数）、作成（作成後にそのデータベースを開く）、削除（名前を再入力して確認。PostgreSQL は接続中のセッションを切断して削除） |
| SQL | サーバー全体向けの SQL コンソール。「対象データベース」で修飾なしの名前を解決するデータベースを選ぶ |
| ステータス | サーバーのバージョン・稼働時間・ステータス変数（名前で絞り込み） |
| 変数 | システム変数（名前で絞り込み） |
| プロセス | 接続中のセッション一覧。「強制終了」で切断 |
| ユーザー | アカウント一覧、権限（GRANT 文）表示、「ユーザーを作成」、「パスワードを変更」、削除 |

## データベース

| タブ | 内容 |
|---|---|
| 構造 | テーブル / ビューの一覧（行数の概算・エンジン・コメント）、テーブル作成。チェックボックスで複数選択して「選択したテーブルをエクスポート」「…を空にする…」「…を削除…」（1 件ならテーブル名、複数ならデータベース名の入力で確認） |
| SQL | データベースを対象にした SQL コンソール（後述） |
| エクスポート | データベース全体を SQL / CSV / JSON でダウンロード（対象テーブルを選択可）。SQL にはルーチン・トリガー・イベントも含められ、MySQL では `DEFINER` 句（ルーチン・トリガー・イベント）を除いて別ユーザーで復元することもできます。ルーチンの区切りは `DELIMITER ;;` です。MariaDB の SEQUENCE は `CREATE SEQUENCE` と現在値からの `RESTART` として、PACKAGE は仕様と本体の順に出力されます。PostgreSQL では制約（CHECK / UNIQUE / EXCLUDE / 外部キーのオプション）、列の照合順序、identity 列のオプション、`UNLOGGED`、継承・パーティション、マテリアライズドビューのインデックス、トリガーの有効状態も復元されます。「DROP TABLE IF EXISTS を付ける」を選ぶと、PostgreSQL ではダンプに含まれるオブジェクトの DROP を依存順にまとめて先頭に出力します（`CASCADE` は使わないため、ダンプ外のオブジェクトが依存している場合は復元がそこで止まります）。MySQL では各 CREATE の直前に DROP を出力します。ビュー・ルーチンはサーバーのカタログに基づく依存順で並びます。MySQL の SQL ダンプはデータベース名を含まないため、別名のデータベースへそのままインポートできます |
| インポート | SQL スクリプト（複数文、`DELIMITER` 対応）または CSV（「取り込み先テーブル」「区切り文字」「1 行目をカラム名として扱う」を指定）を投入 |
| 権限 | このデータベースに対する各ユーザーの現在の権限（すべて / 一部 / なし）と、DB 単位の GRANT / REVOKE ALL |
| ルーチン | ストアドプロシージャ / 関数。「定義を表示」で CREATE 文を取得 |
| トリガー | トリガー一覧と定義 |
| イベント | MySQL のイベントスケジューラ（有効化 / 無効化 / 削除）。PostgreSQL では非対応の旨を表示 |

## テーブル

### 表示（ブラウズ）

- カラム見出しをクリックでソート（昇順 → 降順 → 解除）。Shift + クリックで複数カラム（番号が並べ替え順）。「表示行数」はブラウザに記憶されます
- 「カラム N/M」で表示するカラムを選択（URL に保存）
- 外部キーの値には参照先へのリンク（↗）、主キーには参照元テーブルへのリンク（↵）が付きます
- 絞り込みなしで 10 万行を超えるテーブルは全件カウントを省略し「約 N 行（概算）」を表示します
- **編集**: 行頭の鉛筆でダイアログ編集、セルのダブルクリックでインライン編集（`Enter` で保存 / `Esc` でキャンセル）。コピーアイコンで **行を複製**（自動採番カラムは新しい値）
- **削除**: チェックボックスで選択して「選択行を削除」。確認ダイアログの後に削除されます
- 主キーもユニークキーもないテーブルは、PostgreSQL では `ctid`、MySQL では全カラム一致で 1 行だけを特定します。該当行が 1 件でない場合は変更せずにエラーになります。`ctid` は物理位置なので、他のセッションがその行を更新・削除した後は古い画面からの編集が別の行に当たる可能性があります — 主キーのないテーブルを編集するときは直前に再読み込みしてください（主キーを付けるのが根本対策です）
- ビューは読み取り専用です

### 構造

- カラムの追加・変更・削除、インデックスの追加・削除、外部キーの追加・削除（同じスキーマ内のテーブルへ）、参照元の表示、CREATE 文の表示
- 変更はすべて **生成 SQL のプレビュー → 「実行する」** の順に進みます。TRUNCATE / DROP など元に戻せない操作はオブジェクト名の再入力が必要です

### SQL

- `⌘/Ctrl + Enter` で実行。複数文は文ごとに結果（行 / 影響行数 / エラー位置）を表示し、完了した文から順に描画されます
- 実行中は「キャンセル」で中断できます。「最大行数」を超えた結果は先頭だけを表示します（切り詰めの表示あり）
- 「EXPLAIN」で 1 文の実行計画を表示
- 結果は「CSV」「JSON」で画面に表示されている分をダウンロードできます
- 「保存済みクエリ」に名前を付けて保存（このブラウザに保存）、「履歴」は直近 100 件。入力途中の SQL はタブを移動しても保持されます（このブラウザタブ内）

各実行は自動コミットです。`BEGIN` を発行したまま終了したスクリプトは、接続を返却する前にロールバックされます。

### 検索 / 挿入 / エクスポート / インポート / トリガー / 操作

| タブ | 内容 |
|---|---|
| 検索 | カラムごとの条件（=, ≠, <, >, 「を含む」「で始まる」（ワイルドカード不要）, LIKE, IS NULL …）を組み合わせて絞り込み。結果は「表示」タブに引き継がれます |
| 挿入 | フォームで 1 行を挿入。「既定値を使う」「NULL」をカラムごとに指定（既定値はプレースホルダに表示）。挿入後もこの画面に留まり、続けて入力できます（「一覧へ戻る」で表示へ） |
| エクスポート | このテーブルを SQL / CSV / JSON でダウンロード（構造 / データを選択） |
| インポート | このテーブルへ CSV を投入 |
| トリガー | このテーブルのトリガー |
| 操作 | 「テーブル名を変更」、「テーブルオプション」（コメント。MySQL はエンジン・照合順序・次の AUTO_INCREMENT 値も）、「テーブルをコピー」（「データもコピーする」の有無）、「メンテナンス」（MySQL: ANALYZE / OPTIMIZE / CHECK TABLE、PostgreSQL: ANALYZE / VACUUM / VACUUM FULL）、「テーブルを空にする…」（TRUNCATE）、「テーブルを削除…」（DROP）。ビューでは「ビューを削除…」だけ |

## 値の表し方

| 値 | 表示 / 入力 |
|---|---|
| NULL | *NULL* と斜体で表示。フォームでは「NULL」チェック |
| 空文字 | *（空）* と表示。NULL とは区別されます |
| BIGINT / DECIMAL / 日時 | 精度が落ちる値（2^53 を超える BIGINT、DECIMAL、日時）はサーバーが返す文字列のまま（丸め・タイムゾーン変換なし） |
| JSON / 配列 | 文字列として表示・編集 |
| バイナリ | `[バイナリ N バイト]`。先頭 64 KB まで取得し、フォームからは編集できません（SQL で更新してください） |

## 制限事項

- 1 ページの表示は最大 1,000 行、SQL コンソールの結果は最大 10,000 行
- インポートファイルは 64 MB まで
- 主キーもユニークキーもない MySQL テーブルのエクスポートは安定した順序が取れないため 1 回で全件を読み出します（大きなテーブルではメモリを消費）
- PostgreSQL にはイベントスケジューラがありません（`pg_cron` などの拡張をご利用ください）
- ルーチン・トリガーは一覧と定義の表示のみです（作成・変更は SQL コンソールで。ロードマップ）
