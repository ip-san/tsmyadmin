# E2E（Playwright）のルール

- E2E は本番ビルドを API が配信する。Playwright のプロジェクトは `chromium`（機能）/ `webkit`（機能・Safari 差分）/ `a11y` / `visual-light` / `visual-dark`
- **ビジュアルの 2 つはローカル専用**で、CI は `chromium` / `a11y` / `webkit` だけを、プロジェクトごとの別のジョブ（`e2e-run` の matrix）で並べて実行する（それぞれが自分の DB とサーバーを持つ。必須のチェック名 `e2e` は、3 つが全部通ったかを見るまとめ役のジョブ）（スナップショットは `-darwin` のみ。OS が変わると描画差で落ちるため）。したがって見た目の退行はローカルで `bun run test:e2e` を回したときにしか検出されない
- `bun run test:e2e` は毎回ビルドするが、ポート 3199 / 3198（永続セッションストアの検証用）に古いサーバーが残っていると再利用される（`reuseExistingServer`）。web を変更したら `bun run build` してから実行するか、残っているサーバーを止める
- **サーバーが決めることを確かめない。** 結合の順番、インデックスを使うか、実行計画の形は、DB の版（CI は MySQL 8.0 / 8.4・PostgreSQL 14 / 17・MariaDB）や、ほかのテストが足した行で変わる（手元の 8.4 / 17 では通っても CI で落ちる）。確かめるのは、版によらず決まること（読む表がそろっている、件数、文言）だけにする
- **spec ファイルを別の spec から import しない**（import した側でテストが二重に登録される）。複数の spec が使う手順は、`e2e/helpers.ts` か `e2e/<名前>.ts`（例: `plan.ts`）に置く

## 並行して走るテスト

テストは同じ DB を共有し、同時に走る。

- **準備の SQL は `sqlOn`（`e2e/helpers.ts`）で流す**。`POST /sql` は文が失敗しても 200 で、失敗を結果の 1 つ（`kind: 'error'`）として返すので、`page.request.post` のままだと、準備が失敗しても先へ進み、何も確かめないまま通る（または原因の分からない失敗になる）。待つことが目的の文（ロックの鎖）だけは、結果を見ない
- **自分の表は、自分だけの名前か、自分だけの空間に作る**。表の名前は `scratchName('e2e_…')`（`Date.now()` だけでは同時に走る 2 つがぶつかる）。決まった名前の表を何枚も作るとき、図に自分の表だけを出したいときは `withScratchSpace`（MySQL は専用のデータベース、PostgreSQL は専用のスキーマ。名前は global teardown が掃除する `e2e_db_` / `e2e_schema_`）
- **確かめるのは自分の要素だけにする**。`.first()` で拾うと、同時に走る別のテストの同じ文言（札・件数）で通ってしまう。自分の行（自分の外部キー名の行）、自分の ID（ロックの鎖の元の ID）、自分の目印（文に入れたコメント）で絞る。「全部消えた」（`ロック待ちはありません`）ではなく「自分のものが消えた」を待つ
- **決め打ちの待ち（`waitForTimeout`）で順番を作らない**。サーバーの状態を `expect.poll` で読んで待つ（ロックの鎖: A が眠っている、B が A を待っている、とサーバーが言ってから次を始める。文の目印は、送った直後からプロセス一覧に出るので、それだけでは「実行した」ことにならない）。PostgreSQL の統計（`pg_stat_*`）は少し遅れて届くので、統計を読む画面は、API で数が出るのを待ってから開く
- **後片付けは、準備の途中の失敗でも走らせ、失敗しても元のエラーを隠さない**（`cleanUp` は警告にとどめる。残ったものは `e2e_` の名前で global teardown が掃除する）
